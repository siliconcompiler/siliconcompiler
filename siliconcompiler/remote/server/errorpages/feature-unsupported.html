This deployment does not have the capability you asked for now. A client that read a stale GET /v1 may meet it; so may one that did not read it at all.

What to do

  1. Read feature. Do not retry the request.
  2. Re-read GET /v1’s features before offering the capability again: it is offered only where it is listed.
  3. Do the thing another way — for logs.stream.job, follow each running node instead; for logs.stream, read the node’s logs artifact once the node finishes.

featureREQUIRED A registered features string: logs.stream, logs.stream.job, projects, python.env or jobs.reuse. v1 may register more, and a client that does not know one treats it as a refusal of this request. Where several are missing, the broadest is named.

Where it comes from

GET /v1/jobs/{id}/logs logs.stream, logs.stream.job.
POST /v1/jobs projects; the first string in descriptor.needs this deployment does not offer; or python.env for a job that lists python_packages where this deployment does not install a job’s Python packages. A wheel uploaded there is archive-rejected, reason: "python_package", instead.

A login this deployment does not offer, the device grant included, is not this type: it is unsupported_grant_type, in the OAuth shape, at the two OAuth endpoints.
