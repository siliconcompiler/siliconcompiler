feature-unsupported

This deployment does not support that

501 Not Implemented https://siliconcompiler.com/server-errors/feature-unsupported

This deployment does not have the capability you asked for now. A client that read a stale GET /v1 may meet it; so may one that did not read it at all.

What to do

  1. Read feature. Do not retry the request.
  2. Re-read GET /v1’s features before offering the capability again: it is offered only where it is listed.
  3. Do the thing another way — for logs.stream.job, follow each running node instead; for logs.stream, read the node’s logs artifact once the node finishes.

The body

{
  "type":     "https://siliconcompiler.com/server-errors/feature-unsupported",
  "title":    "This deployment does not support that",
  "status":   501,
  "detail":   "...",
  "instance": "/v1/jobs/01J9...",
  "feature":  "logs.stream",  // REQUIRED on this type
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}
Member
featureREQUIRED A registered features string: logs.stream, logs.stream.job, projects, python.env or jobs.reuse. v1 may register more, and a client that does not know one treats it as a refusal of this request. Where several are missing, the broadest is named.
trace_idoptional The request’s W3C trace id. Quote it in a support request.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

GET /v1/jobs/{id}/logs logs.stream, logs.stream.job.
POST /v1/jobs projects, or the first string in descriptor.needs this deployment does not offer.
GET /v1/jobs/{id} As a rejected job’s error: python.env, raised while staging for a job carrying a Python environment file it did not declare.

A login this deployment does not offer, the device grant included, is not this type: it is unsupported_grant_type, in the OAuth shape, at the two OAuth endpoints.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • Where this arrived on a job’s error rather than on a request, there is no trace_id: quote the job’s id, the one identifier that finds the run.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

not-ready is transient and should be retried.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
