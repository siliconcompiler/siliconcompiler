declared-mismatch

The manifest contradicts the descriptor

422 Unprocessable Content https://siliconcompiler.com/server-errors/declared-mismatch

What the uploaded manifest says disagrees with what the job was created with — a different design or job name, or a flow the descriptor did not describe. The server trusts the manifest and refuses the contradiction.

What to do

  1. This is usually a client bug: the client builds both from the same project. Report it with the trace_id.
  2. If you built the upload by hand, make the archive’s manifest match the job you created.

The body

{
  "type":     "https://siliconcompiler.com/server-errors/declared-mismatch",
  "title":    "The manifest contradicts the descriptor",
  "status":   422,
  "detail":   "...",
  "instance": "/v1/jobs/01J9...",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}

detail is prose and may be reworded at any time. Branch on type — never parse detail.

Where it comes from

POST /v1/jobs/{id}/submit At re-derivation, after the archive is opened.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

archive-rejected is the archive itself being unsafe, not its contents disagreeing.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
