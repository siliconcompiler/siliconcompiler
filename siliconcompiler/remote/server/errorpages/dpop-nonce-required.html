dpop-nonce-required

DPoP nonce required

401 Unauthorized https://siliconcompiler.com/server-errors/dpop-nonce-required

The server requires a nonce in the DPoP proof and has just supplied one. The response carries WWW-Authenticate: DPoP error="use_dpop_nonce" and the nonce in a DPoP-Nonce header. A missing or stale nonce is always this, never invalid-dpop-proof.

What to do

  1. Sign a fresh proof carrying the nonce from DPoP-Nonce, and retry the request once.
  2. Keep one nonce per origin: the stream host’s nonce is not the API’s.

The body

HTTP/1.1 401 Unauthorized
WWW-Authenticate: DPoP error="use_dpop_nonce"
DPoP-Nonce: eyJ7S_zG.eyJH0-Z.HX4w-7v

{
  "type":     "https://siliconcompiler.com/server-errors/dpop-nonce-required",
  "title":    "DPoP nonce required",
  "status":   401,
  "instance": "/v1/jobs",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}

At the two OAuth endpoints

At POST /v1/auth/token and POST /v1/auth/device the same condition is answered in the OAuth shape: 400, {"error": "use_dpop_nonce"}, with the nonce in DPoP-Nonce. The client does the same thing.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

invalid-dpop-proof is a proof that failed a check: malformed, replayed, or signed by the wrong key. That one fails and is not retried, except once after correcting the clock for a proof refused for its time. This one is always retried once.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
