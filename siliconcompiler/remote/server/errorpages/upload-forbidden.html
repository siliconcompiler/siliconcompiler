upload-forbidden

Upload of that resource is not allowed

422 Unprocessable Content https://siliconcompiler.com/server-errors/upload-forbidden

Your upload carries files that belong to a controlled resource — a PDK or library under an agreement — which your account may not upload. The deployment supplies its own copy of controlled resources; it does not accept one from you.

What to do

  1. Read resource_kind and resource to see which.
  2. Use the deployment’s copy: reference the resource from its released source instead of a local or editable one, so its files are not uploaded.
  3. If you need to run a modified copy, that is a permission for whoever administers your account.

Only a resource the deployment controls can be refused this way. A deployment with no controlled resources, such as the reference sc-server, never returns it.

resourceREQUIRED Its name.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

POST /v1/jobs/{id}/submit While the archive is extracted — the earliest the server can see what it carries.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

archive-rejected is also raised during extraction, and is a safety failure of the archive itself, not a policy about its contents. The fix differs.

resource-unavailable is the opposite case: files the server needed and did not get.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
