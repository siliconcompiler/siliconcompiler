upload-forbidden

Upload of that resource is not allowed

422 Unprocessable Content https://siliconcompiler.com/server-errors/upload-forbidden

Your upload carries files of a controlled resource — a PDK or library under an agreement — which your account may not upload. The deployment supplies its own copy of controlled resources; it does not accept one from you. The job is rejected and the upload deleted.

What to do

  1. Read detected. attribution: your manifest attributes the file to a controlled resource. content: the file’s bytes match one, whatever the manifest calls it.
  2. Read member, the archive entry that was refused, and resource_kind.
  3. Use the deployment’s copy: reference the resource from its released source instead of a local or editable one, so its files are not uploaded.
  4. If you need to run a modified copy, that is a permission for whoever administers your account.

Only a resource the deployment controls can be refused this way. A deployment with no controlled resources, such as the reference sc-server, never returns it.

Member
resource_kindREQUIRED pdk, library or fpga.
detectedREQUIRED attribution or content: how the member was found to be controlled.
memberREQUIRED The archive entry, bounded. Named only once the archive has passed its safety checks.
resourceOPTIONAL Its name — present only when you hold a grant on it. Otherwise naming it would confirm what the deployment’s catalogue holds.
trace_idoptional The request’s W3C trace id. Quote it in a support request.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

POST /v1/jobs/{id}/submit While the archive is extracted — the earliest the server can see what it carries.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • Where this arrived on a job’s error rather than on a request, there is no trace_id: quote the job’s id, the one identifier that finds the run.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

archive-rejected is also raised during extraction, and is a safety failure of the archive itself, not a policy about its contents. The fix differs.

resource-unavailable is the opposite case: a resource the server needed and could not get.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
