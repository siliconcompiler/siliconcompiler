artifact-not-approved

Artifact not approved

403 Forbidden https://siliconcompiler.com/server-errors/artifact-not-approved

This artifact is held back by a rule about the object itself, not about you or the resources behind it. It is withheld, it is an issue testcase, or it is a node archive that holds something that is, or a member deleted on its own — or this deployment does not hand its kind over the API.

What to do

  1. Look at the artifact in the listing: a fetchable: false object with an access_request_url has a path to approval — follow it.
  2. Without one there is no request to make over the API. A deployment with a web portal may offer the object there.
  3. For a node archive, fetch what it holds that you can have — its manifest, log and reports are listed on their own.

The body

{
  "type":     "https://siliconcompiler.com/server-errors/artifact-not-approved",
  "title":    "Artifact not approved",
  "status":   403,
  "detail":   "...",
  "instance": "/v1/jobs/01J9...",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}

detail is prose and may be reworded at any time. Branch on type — never parse detail.

Where it comes from

GET /v1/jobs/{id}/artifacts/{artifact_id} The object’s own gate.
GET /v1/jobs/{id}/logs A node’s archived log, held back the same way.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

entitlement-denied is your account not holding a resource the artifact derives from, and names it.

not-ready is an artifact still being described, and is worth asking about again.

not-found is an artifact whose bytes are gone.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
