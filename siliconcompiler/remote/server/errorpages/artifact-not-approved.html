This artifact is held back by a rule about the object itself, not about you or the resources behind it. It is withheld, it is an issue testcase, or it is a node archive that holds something that is, or a member deleted on its own — or this deployment does not hand its kind over the API.

What to do

  1. Look at the artifact in the listing: a fetchable: false object with can_request_access: true has a path to approval — open its page from POST /v1/auth/browser with {"artifact_id": "<id>"}, and ask there.
  2. With can_request_access: false there is no request to make. A deployment with a web portal may offer the object there.
  3. For a node archive, fetch what it holds that you can have — its manifest, log and reports are listed on their own.
