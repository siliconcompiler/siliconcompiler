upload-digest-mismatch

Upload digest does not match

422 Unprocessable Content https://siliconcompiler.com/server-errors/upload-digest-mismatch

The digest you sent with the submit is not what storage holds for this job. Nothing was opened: the check comes before extraction, precisely so the bytes cannot change between the check and the use.

What to do

  1. Upload again to the grant, then submit with the digest of exactly those bytes.
  2. A transfer that was cut short is the usual cause.

detail is prose and may be reworded at any time. Branch on type — never parse detail.

Where it comes from

POST /v1/jobs/{id}/submit Before the archive is opened.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

archive-rejected is an archive that arrived intact and broke a rule once opened.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
