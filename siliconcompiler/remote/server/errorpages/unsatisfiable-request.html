unsatisfiable-request

This server cannot provide that

422 Unprocessable Content https://siliconcompiler.com/server-errors/unsatisfiable-request

The job needs a tool, PDK or library this deployment does not offer in any form. Nothing about your account or your request’s timing changes that.

What to do

  1. Read resource_kind and resource to see what was missing.
  2. Run the job against a deployment that offers it, or ask this one’s operator to add it.

Member
resource_kindREQUIRED pdk, tool, library or fpga.
resourceREQUIRED Its name, as the catalogue spells it.
trace_idoptional The same W3C trace id as the response header. Quote it in a support request.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

POST /v1/jobs The descriptor names something this deployment does not offer.
POST /v1/jobs/{id}/submit The flow re-derived from the manifest reaches for it.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

entitlement-denied is the same catalogue and a different question: the deployment has it and you may not use it.

software-unavailable is software the deployment has, just not in the version you asked for.

resource-unavailable is a PDK, library or FPGA device the flow needs whose files neither the server holds nor your upload carried.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
