account-not-provisioned

Your account is not set up on this deployment

403 Forbidden https://siliconcompiler.com/server-errors/account-not-provisioned

You are signed in, and this deployment has no account for you on the machines that run jobs — a POSIX account, where a job runs as its owner. Nothing about the job is wrong.

What to do

  1. Ask the deployment’s operator to set up your account, then submit again. Retrying before then gets the same answer.

The body

{
  "type":     "https://siliconcompiler.com/server-errors/account-not-provisioned",
  "title":    "Your account is not set up on this deployment",
  "status":   403,
  "detail":   "...",
  "instance": "/v1/jobs",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}

detail is prose and may be reworded at any time. Branch on type — never parse detail.

Where it comes from

POST /v1/jobs At create.
POST /v1/jobs/{id}/submit At submit.

The reference sc-server never raises it: it sets an account up on first contact.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

entitlement-denied is a resource you may not use. This one is you having nowhere to run, whatever the job uses.

insufficient-scope is a token whose scope does not cover the call.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
