scheduler-lost

The scheduler lost this job

Not an HTTP response https://siliconcompiler.com/server-errors/scheduler-lost

The scheduler the job was handed to no longer knows about it, and the server stopped believing it is running. The job ran, or was going to, and went away rather than failing.

What to do

  1. Submit the job again.

The body

{
  "id":    "01J9...",
  "state": "failed",
  "error": {
    "type":   "https://siliconcompiler.com/server-errors/scheduler-lost",
    "title":  "The scheduler lost this job",
    "detail": "..."
  }
}

detail is prose and may be reworded at any time. Branch on type — never parse detail.

Where it comes from

GET /v1/jobs/{id} As the job’s error.type, once the server reconciles it.

Getting help with your specific failure

This type arrives inside a job, not on a request, so there is no trace_id on it. Quote the job’s id when you escalate — it is the one identifier that finds the run on the server, its scheduler job and its logs.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your job — the job id is what connects the two.

What this is not

run-failed is a run that ended with a failure. This one did not end at all, as far as anyone can tell.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
