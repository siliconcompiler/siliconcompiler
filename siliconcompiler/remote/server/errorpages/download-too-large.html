download-too-large

Download too large

403 Forbidden https://siliconcompiler.com/server-errors/download-too-large

The artifact you asked for is larger than this deployment serves over the API, limits.max_download_bytes. It is there and you may have it; it is refused for its size alone. The ceiling is static, so waiting and retrying return the same answer.

What to do

  1. Compare the artifact’s size in the listing with limits.max_download_bytes in GET /v1.
  2. Download it from the web portal, which is the way past this ceiling. The API has none.
  3. For a node’s output, the smaller logs and reports artifacts may be under the ceiling where the whole node archive is not.

Formerly 429 limit-exceeded with limit: "max_download_bytes" and a Retry-After. That was a retry loop: a client obeying Retry-After on a ceiling that never refills retries for ever.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

GET /v1/jobs/{id}/artifacts/{artifact_id} The object is larger than the ceiling.
GET /v1/jobs/{id}/logs A finished node’s log archive, where the redirect to it would hand you an object over the ceiling.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

limit-exceeded is a ceiling that refills, and carries Retry-After.

upload-too-large is the same kind of ceiling on what you send. It is a 413 because it is the request’s own size; here the request is small and the answer is not.

artifact-not-approved is an object you may not download at all, whatever its size.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
