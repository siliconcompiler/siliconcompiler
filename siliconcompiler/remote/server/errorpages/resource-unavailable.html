resource-unavailable

This server does not hold that resource

422 Unprocessable Content https://siliconcompiler.com/server-errors/resource-unavailable

The flow needs a PDK, a standard-cell library or an FPGA device that this deployment does not hold, and its files were not in your upload. The job was refused when the server opened the archive, before anything ran.

What to do

  1. Read resource_kind and resource to see which.
  2. Use one this deployment holds, or make sure its files go up with the job. A client uploads a PDK’s, library’s or FPGA device’s files only when they come from a local path or a package installed editable — one fetched from a release stays behind, because a server is expected to have its own.

The body

Member
resource_kindREQUIRED pdk, library or fpga.
resourceREQUIRED Its name.
trace_idoptional The same W3C trace id as the response header. Quote it in a support request.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

POST /v1/jobs/{id}/submit After the archive is opened, when the flow is re-derived from the manifest.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

resource-unresolved is the server not being able to work out which resource the flow needs. Here it knows which, and does not have it.

entitlement-denied is a resource the deployment has and you may not use.

upload-forbidden is files you did upload that you were not allowed to.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
