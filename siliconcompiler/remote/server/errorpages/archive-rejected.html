archive-rejected

Archive rejected

422 Unprocessable Content https://siliconcompiler.com/server-errors/archive-rejected

While the job stages, the uploaded archive broke one of the rules an archive must follow, or cannot be run as sent. The job is rejected, with this on its error.

What to do

  1. Read reason, and fix what it names, in a new job.
  2. member_count and expanded_bytes are published limits (max_archive_members, max_archive_expanded_bytes): send less.
  3. ratio is an early abort on the compression ratio, where the deployment applies one. link_member, device_member and traversal are safety rules: the archive carries a link that resolves outside it, a device file, or a member named with .., written twice, or written through a link. A link that resolves inside the archive is kept as a link. A client builds none of these; a hand-built archive can.
  4. missing_manifest and invalid_manifest: the archive holds no manifest at its root, or one that cannot be read.
  5. unrequested_member is a member the server did not ask for: in the first archive, anything but the manifest, sc_collected_files/ and <step>/<index>/outputs/ for a node the run reads and does not run; in a follow-up — one sent after the server asked in upload_sources — a dataroot or a wheel it did not ask for.
  6. missing_member is the opposite: the flow reads a value the client should have sent, or the results of a node the run reads and does not run, and nothing supplies it. detail names the keypath or the node. A client sends what the flow’s tasks require, so this is a client bug, or a task whose requirements leave out a file it reads.
  7. python_package is an uploaded wheel, under sc_collected_files/python/, that is not pure — tagged none-any, with no .so, .pyd or .dylib — is malformed, overlaps a distribution python_packages lists or another wheel, or arrives on a deployment without python.env. detail names the wheel. The client builds every wheel, so this is a client bug.
  8. breakpoint is a node with option,breakpoint set: the run would stop for a person to look, and nobody is at a remote run. detail names the node. Clear the breakpoint for it.
  9. interactive_task is a node whose task opens a window for a person — every ShowTask, OpenROAD’s WebTask — which nobody is at a remote run to use. detail names the node and its task. A ScreenshotTask renders the same view headless and is allowed.
  10. extension is a member whose file extension the deployment’s allowlist does not admit. detail names the member. That is deployment policy, not a safety rule: only a deployment with a member-extension allowlist raises it. The reference sc-server has none — it admits every extension — and never raises it.

The body

{
  "id":    "01J9...",
  "state": "rejected",
  "error": {
    "type":   "https://siliconcompiler.com/server-errors/archive-rejected",
    "title":  "Archive rejected",
    "status": 422,
    "detail": "...",
    "reason": "expanded_bytes"   // REQUIRED on this type
  }
}
Member
reasonREQUIRED member_count, expanded_bytes, ratio, link_member, device_member, traversal, missing_manifest, invalid_manifest, unrequested_member, missing_member, python_package, breakpoint, interactive_task or extension. An unrecognised value means act on the type alone.

detail is prose and may be reworded at any time. Branch on type, then on reason — never parse detail.

Where it comes from

GET /v1/jobs/{id} As a rejected job’s error: found while the job stages, after submit answered 202 — the first archive or a follow-up.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the request’s W3C trace id: the one your client’s traceparent carried, where it sent one, so your own logs can find it too.
  • Where this arrived on a job’s error rather than on a request, there is no trace_id: quote the job’s id, the one identifier that finds the run.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

upload-too-large is the archive being too large to accept at all.

upload-forbidden is a policy about the restricted material an archive carries — whose it is, not what shape the archive takes — and not a safety failure.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
