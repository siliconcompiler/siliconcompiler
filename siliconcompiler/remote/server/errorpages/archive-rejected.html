archive-rejected

Archive rejected

422 Unprocessable Content https://siliconcompiler.com/server-errors/archive-rejected

The uploaded archive arrived intact and broke one of the rules an archive must follow before the server will expand it.

What to do

  1. Read violation.
  2. member_count and expanded_bytes are published limits (max_archive_members, max_archive_expanded_bytes): send less.
  3. ratio, link_member, device_member and traversal are safety rules: the archive compresses implausibly, or carries a link, a device file or a path that escapes the job. A client builds none of these; a hand-built archive can.
  4. unrequested_member is a follow-up archive — one sent after the server asked for sources in upload_sources — carrying something it did not ask for. A second upload may not replace what the first carried after the server checked it: send only what was asked.
  5. missing_member is the opposite: the flow reads a file the client should have sent — the design, anything local or editable, or something the server asked for — and the archive does not carry it. detail names the keypath. A client sends what the flow’s tasks require, so this is a client bug, or a task whose requirements leave out a file it reads. It also covers the results of a node a run that starts part-way through its flow reads and does not run, sent neither in the archive nor as a job in continues_from; detail then names the node.
  6. environment_file is a node’s Python environment file — python-env/<step>/<index>/requirements.txt — outside its format, or for no node of the flow. detail names the file and the line. The client writes that file and the user never edits it, so this is a client bug.
  7. breakpoint is a node with option,breakpoint set: the run would stop for a person to look, and nobody is at a remote run. detail names the node. Clear the breakpoint for it.
  8. interactive_task is a node whose task opens a window for a person — every ShowTask, OpenROAD’s WebTask — which nobody is at a remote run to use. detail names the node and its task. A ScreenshotTask renders the same view headless and is allowed.
  9. extension is a member whose file extension the deployment’s allowlist does not admit. detail names the member. That is deployment policy, not a safety rule: only a deployment with a member-extension allowlist raises it. The reference sc-server has none — it admits every extension — and never raises it.

Member
violationREQUIRED member_count, expanded_bytes, ratio, link_member, device_member, traversal, unrequested_member, missing_member, environment_file, breakpoint, interactive_task or extension.
trace_idoptional The same W3C trace id as the response header. Quote it in a support request.

detail is prose and may be reworded at any time. Branch on type, and read the members above for the specifics — never parse detail.

Where it comes from

POST /v1/jobs/{id}/submit While the archive is opened, after its digest has matched — the first archive or a follow-up.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

upload-too-large is the archive being too large to accept at all.

upload-forbidden is a policy about the restricted material an archive carries — whose it is, not what shape the archive takes — and not a safety failure.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
