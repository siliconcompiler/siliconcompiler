Unsupported media type

415 Unsupported Media Type https://siliconcompiler.com/server-errors/unsupported-media-type

The request body’s Content-Type is not one this endpoint accepts.

What to do

  1. Send application/json to the JSON endpoints.

An untyped answer is expected here. This refusal is often produced below the request handler — by routing, the framework or a proxy — and then it arrives as the web server’s own page, not as application/problem+json, and has no type at all. Treat a non-problem+json 415 exactly as you would this type.

The body

{
  "type":     "https://siliconcompiler.com/server-errors/unsupported-media-type",
  "title":    "Unsupported media type",
  "status":   415,
  "detail":   "...",
  "instance": "/v1/jobs/01J9...",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736"
}

detail is prose and may be reworded at any time. Branch on type — never parse detail.

Where it comes from

any endpoint with a body
POST /v1/auth/device/{user_code} The approval leg takes application/json only.

Getting help with your specific failure

Two members of the body identify your exact request. Quote both when you escalate — with them, whoever helps you finds the one request instead of searching a five-minute window.

  • trace_id — the correlation id. The same value is on the response as a header, so it is in your logs even if the body is not.
  • instance — the request this happened to.

This page documents the error type. It is the same page for everyone who hits it and it cannot see your response — trace_id is what connects the two.

What this is not

not-acceptable is about what you accept back.

Normative definition: the error type registry in the SiliconCompiler v1 API contract. This page is a rendering of it — where the two disagree, the registry is right.
