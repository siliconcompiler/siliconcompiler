# Screenshots

**Everything in this directory goes stale and nothing will tell you when.**

These are captures of things that change without touching the docs: tool GUIs,
terminal output, rendered layouts, email bodies. Unlike the `.dot` diagrams under
`_images/`, which Sphinx renders from source on every build, nothing here can be
regenerated by the build. If the summary table gains a metric or a step is
renamed, the picture keeps showing the old one and the build stays green.

That is the whole reason this directory is separate: so it is obvious which
images need a human to look at them periodically, and which do not.

## What is here

| Path | Shows | Refresh when |
|---|---|---|
| `dashboard/` | `sc-dashboard` panels | the dashboard UI changes |
| `email/` | node and summary notification emails | the email templates change |
| `hardened/` | `mod_and` and `top` layouts from `examples/macro_reuse` | the example or the PDK changes enough to look different |
| `asic_demo_result.png` | the PNG the ASIC demo leaves behind | the demo design or the screenshot task changes |
| `picorv32_layout.png`, `picorv32_ram_layout.png` | `examples/picorv32` layouts | the example changes |
| `summary_table.png` | `Project.summary()` terminal output | the metric set or step names change |

`summary_table.png` is the standing example of the failure mode: it shows step
names (`import0`, `syn0`, `export0`) from a flow that no longer exists.

## Before adding one

Ask whether the thing is capturable some other way, because anything else is
cheaper to keep true:

- A **flowgraph or dependency graph** renders from the example script — use the
  `scflowgraph` / `scdepgraph` directives (`_ext/graphgen.py`).
- A **diagram you drew** belongs in `_images/` as a `.dot` file.
- **Terminal output** is usually better as a `code-block`, which is greppable,
  copy-pasteable, screen-reader accessible, and diffable when it changes.

A screenshot is the right answer when the point *is* the pixels: a GUI, a
rendered layout, a colour-coded view.

## Adding one

Put it in the table above, in the subdirectory that matches what it shows, and
reference it by an absolute path so it does not depend on where the page sits:

```rst
.. image:: /_screenshots/dashboard/dashboard_header.png
```

Prefer PNG, crop to the point being made, and keep it under a few hundred KB —
these are committed to the repository forever.
